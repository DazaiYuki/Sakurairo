## 二、清理：两条对不存在 handle 的 enqueue

主题在 PJAX 开启时 enqueue 4 个区块样式 handle，其中两个在 WP 7.1.2 中
**已不存在**：

| handle | WP 7.1.2 现状 |
| --- | --- |
| `wp-block-library` | ✓ 存在（script-loader.php:300） |
| `wp-block-library-theme` | ✓ 存在（script-loader.php:1697） |
| `wp-block-library-comments` | ✗ 全核无注册、无样式文件 |
| `wp-block-library-widgets` | ✗ 全核无注册、无样式文件 |

这两个 handle 对应的样式早已并入 `block-library/style.min.css` 主文件
（本地 `wp-includes/css/dist/block-library/` 下已无 comment / widget 样式文件）。
enqueue 不存在的 handle 是静默空操作——不报错、无输出，纯粹是历史遗留。

**改动**：删除这两条调用（functions.php），并附注释说明原因。

**验证**：

- 删除前后页面 `<link>` 输出完全一致（本就是 no-op）
- 视觉回归 27/28 一致；唯一差异 `desktop-light-07-search-empty`（0.013%）
  为该页已知抖动（幅度在不同采集间随机变化 0.013% → 0.37%，dark 版稳定一致，
  见工具 README「已知的最后一个抖动页」），与本次改动无关——
  本次删除在技术上不可能影响渲染（handle 不存在，页面输出无痕迹）

## 三、扫描方法与误报说明

**WP 废弃函数**：从 `wp-includes/*.php` 与 `wp-admin/includes/*.php` 提取全部
429 个带 `@deprecated` 标记的函数名，反向 grep 主题 PHP（排除 kirki /
update-checker / opt/classes 三个内部库目录）。

初扫报 61 处，**全部为误报**，两类原因：

1. PHP 内置函数与 WP 废弃函数同名（`reset` / `parse_url` / `escape`）；
2. 类方法定义 `__construct`（WP 5.3 废弃的是 PHP4 风格「与类同名」构造函数，
   主题用的是 PHP5+ 标准 `__construct`，不受影响）。

过滤后真实命中 **0 处**。

**"嵌套三元"259 处为扫描器误报**：正则把 PHP 替代语法（`if: ... endif;`）
中的冒号误配为三元运算符。运行时实测（7 类页面，`php_notice_filter = inner`
即不干预 error_reporting 的状态下）**Deprecated / Warning / Notice 全部 0 条**，
以运行时事实为准。
